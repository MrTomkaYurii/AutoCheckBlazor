# AutoCheck — Огляд проекту

## Що це

Веб-платформа для автоматичної перевірки лабораторних робіт з курсу «ООП на C#».
Кафедра комп'ютерних наук, ЧНУ ім. Ю. Федьковича. ~100 студентів, 22 лаби.

Студент здає коміт зі свого GitHub-репо → сервер клонує репо й аналізує код через
Gemini → викладач приймає захист і виставляє фінальну оцінку.

## Стек

| Компонент | Технологія |
|-----------|-----------|
| Frontend + Backend | Blazor Server (.NET 10) |
| БД | SQLite + EF Core 9 (`EnsureCreated`, без міграцій) |
| UI компоненти | MudBlazor 9 + власний CSS (dark glassmorphism) |
| Автентифікація | ASP.NET Core Identity (+ Google OAuth, опційно) |
| AI-перевірка | Gemini 2.5 Flash (REST API) |
| Markdown | Markdig |
| Git | локальний `git` CLI (grading) + GitHub REST API (UI) |

## Ролі

- **Студент** — реєструється, здає лаби, бачить оцінки/прогрес, редагує профіль (ім'я, email, GitHub URL/токен)
- **Викладач** — приймає захисти, виставляє оцінки, керує лабами/групами/студентами, розбирає сигнали плагіату

## Два режими перевірки

1. **Авто-перевірка** — студент здає коміт → git clone → витяг коду per-task → Gemini повертає done/issues → score
2. **Ручна перевірка** — викладач у GradeDialog виставляє оцінку захисту, live рахується фінал

## Формула оцінки

```
AutoScore = Scoring.Weighted(...)  — зважена за складністю (⭐) середня по завданнях
            (найкраща з усіх спроб; поріг 50 — інакше лаба відхилена)
Фінал     = 0.4 × AutoScore + 0.6 × DefenseScore
```

## Запуск

```bash
dotnet run             # Blazor на :5186 (dev — без контейнерів)
```

Для авто-перевірки: встановлений `git` + `Gemini:ApiKey` у `appsettings.json`.

Тестові акаунти:
- `student@test.com` / `Test1234!` — seed-студент
- `teacher@test.com` / `Test1234!` — seed-викладач

## Ключові факти

- `autocheck.db` — SQLite у кореневій теці (включно з Identity-акаунтами). Видалити + перезапустити = повний скид до seed-даних. Щоденний авто-бекап (`BackupService`).
- 22 лабораторних парсяться з `content/labs/lab-*/instructions.md` при першому старті; вимоги перевірки — у `checks.json` кожної лаби (заповнені для всіх 22).
- Студенти реєструються самі; seed-студенти — демо для викладача, не реальні акаунти.
- Grading **клонує** репо локально (`git`) і аналізує через Gemini; GitHub API використовується лише в UI для вибору гілок/комітів.
- GitHub-токен студента зберігається зашифрованим (DataProtection, `TokenProtector`).
