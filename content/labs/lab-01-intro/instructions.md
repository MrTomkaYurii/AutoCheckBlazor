## Контекст

Курс — це **одна система, яку ви будуєте 22 лаби поспіль**. Починаючи з Лаби 03,

З Лаби 03 стартує основний проєкт, який далі росте до кінця курсу.

Ця лаба веде вас за руку: від порожньої теки до працюючого рішення з 8 завданнями.

До кінця курсу ваш репозиторій виглядатиме так:

```
<ваш-репозиторій>/

├── oop-course.sln          ← рішення: посилається на всі проєкти нижче
├── Lab01/                   ← Лаба 01 — базовий C# (окремий проєкт)
│   ├── Lab01.csproj
│   ├── Program.cs
│   └── Task1.cs … Task8.cs
├── Lab02/                   ← Лаба 02 — масиви (окремий проєкт)
│   ├── Lab02.csproj
│   └── …
└── ClinicApp/               ← Лаби 03–22 — основний проєкт, росте весь курс
    ├── ClinicApp.csproj
    ├── Program.cs
    ├── Models/  Managers/  …
```

> `ClinicApp` — назва для еталонного домену (клініка). Свій проєкт назвіть за
> власним доменом: `HotelApp`, `LibraryApp` тощо. Теки `Lab01/` і `Lab02/` —
> завжди з такими іменами.

**Одне правило зв'язує теки, гілки й коміти:**

| Одиниця | Чому дорівнює | Приклад |
|---------|---------------|---------|
| Тека з кодом | одній лабі (для 01–02) або всьому основному проєкту (03+) | `Lab01/`, `ClinicApp/` |
| Гілка git | одній лабі | `Lab-01`, `Lab-03` |
| Коміт | одному завданню | `Lab01 Task03` |
| Злиття в `main` | завершеній лабі (лише з Лаби 03) | `Merge Lab-03: Defining Classes` |

Тобто: працюючи над Задачею 3 Лаби 1, ви **на гілці `Lab-01`**, редагуєте файли
**в теці `Lab01/`**, і в кінці робите **один коміт `Lab01 Task03`**.

## Git у курсі — короткий підсумок

Повне пояснення (staging, `.gitignore`, авторизація GitHub, типові помилки) —
у **[Git Воркшопі](https://tomka.space/git-workshop/)**. Тут — лише цикл однієї лаби:

1. `git checkout main` → `git checkout -b Lab-XX` — нова гілка від `main`.
2. Виконали завдання → `git add <файли>` → `git commit -m "LabXX TaskYY"`.
3. Повторюєте крок 2 для кожного завдання.
4. `git push -u origin Lab-XX` — гілка потрапляє на GitHub (резервна копія).
5. **З Лаби 03** — коли всі завдання лаби готові, гілка зливається в `main`:
   `git checkout main` → `git merge --no-ff Lab-XX` → `git push`.

> ### Пам'ятайте це до кінця курсу
>
> **Кожна лаба = окрема гілка `Lab-XX`, що відходить від `main`.**
> З Лаби 03 кожна така гілка після завершення **зливається назад у `main`** —
> так основне дерево росте лаба за лабою.
>
> **Виняток — Лаби 01 і 02.** Це тренажери синтаксису, а не частина системи.
> Їхні гілки ви **пушите на GitHub, але НЕ зливаєте в `main`**. Основне дерево
> `main` фактично стартує з Лаби 03.

**Формат повідомлення коміту:** `LabXX TaskYY` — номер лаби, пробіл, номер
завдання, обидва по дві цифри. Приклад: `Lab01 Task01`. Коротко й однотипно —
щоб коміти легко читались у `git log --oneline`.

## Як виконувати завдання

Кожне завдання — окремий файл у теці `Lab01/` (`Task1.cs`, `Task2.cs` …): клас
`TaskN` з єдиним статичним методом `Run()`. Файл додаєте просто як новий `.cs`
у теку `Lab01/` (у Visual Studio: ПКМ на проєкті → Add → Class).

У `Lab01/Program.cs` лишається один рядок-виклик — змінюйте номер після кожного завдання:

```csharp
// Дробові числа вводимо з КРАПКОЮ незалежно від регіональних налаштувань Windows.
System.Threading.Thread.CurrentThread.CurrentCulture =
    System.Globalization.CultureInfo.InvariantCulture;

Task1.Run();   // → Task2.Run() → Task3.Run() → ...
```

> Перший рядок обовʼязковий. Без нього на системі з українською локаллю
> `double.Parse("1.75")` кине `FormatException`, бо очікує кому як десятковий
> роздільник. `InvariantCulture` фіксує крапку.
> Документація: [CultureInfo.InvariantCulture](https://learn.microsoft.com/dotnet/api/system.globalization.cultureinfo.invariantculture).

Після кожного завдання — коміт `Lab01 TaskNN`.

### Один знак `!` після `Console.ReadLine()`

У проєкті увімкнено `<Nullable>enable</Nullable>` (стандартна опція `dotnet new`).
Через неї компілятор знає, що `Console.ReadLine()` теоретично може повернути
`null` (наприклад, якщо ввід закінчився), і **попереджає**, коли ви одразу
передаєте результат у `double.Parse(...)`.

При інтерактивному вводі рядок завжди є, тому пишемо:

```csharp
double weight = double.Parse(Console.ReadLine()!);
```

Знак `!` (null-forgiving) означає «я гарантую, що тут не `null`» і прибирає
попередження. Повноцінно тему nullable-типів розберемо в Лабі 03; поки що просто
ставте `!` після `Console.ReadLine()`.

## Задача 1. ІМТ пацієнта ⭐

### Умова

Напишіть програму, яка зчитує вагу та зріст пацієнта і розраховує **Індекс маси тіла (ІМТ)**.

**Формула:** `ІМТ = вага / (зріст × зріст)`

### Формат вводу

| Рядок | Поле  | Тип      |
|-------|-------|----------|
| 1     | вага  | `double` (кг) |
| 2     | зріст | `double` (м)  |

### Приклади

| вага | зріст | Вихід        |
|------|-------|--------------|
| `70` | `1.75` | `ІМТ: 22.86` |
| `90` | `1.80` | `ІМТ: 27.78` |
| `55` | `1.62` | `ІМТ: 20.96` |

### Підказки

1. **Ввід.** Консоль віддає текст, а не число. Прочитайте рядок і перетворіть
   його на `double`. Зʼясуйте в документації різницю між `double.Parse` і
   `double.TryParse` — і чому для навчальних завдань поки достатньо `Parse`.
2. **Два значення — два рядки вводу.** Вага і зріст читаються послідовно, кожен
   зі свого рядка. Порядок — той самий, що у «Формат вводу».
3. **Обчислення.** Формула з умови перекладається в один вираз. Памʼятайте про
   пріоритет операцій: `зріст × зріст` має бути в дужках.
4. **Тип результату.** Ділення двох `double` дає `double` — це те, що потрібно.
5. **Вивід із округленням.** Потрібно рівно два знаки після коми. Це робота
   *форматування при виводі*, а не окремого округлення: знайдіть у документації
   стандартний числовий формат `F` та як застосувати його в інтерпольованому
   рядку (`$"..."`). Саме округлення формату пояснює, чому `20.9572` на екрані
   стає `20.96`.

📖 Документація:
- [double.Parse](https://learn.microsoft.com/dotnet/api/system.double.parse) та [double.TryParse](https://learn.microsoft.com/dotnet/api/system.double.tryparse)
- [Типи з плаваючою комою (`double`)](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/floating-point-numeric-types)
- [Стандартні числові формати (`F2`)](https://learn.microsoft.com/dotnet/standard/base-types/standard-numeric-format-strings#fixed-point-format-specifier-f)
- [Інтерполяція рядків](https://learn.microsoft.com/dotnet/csharp/language-reference/tokens/interpolated)

### Адаптація до вашого домену

| Домен | Формула | Поле 1 | Поле 2 | Вихід |
|-------|---------|--------|--------|-------|
| Готель | завантаженість = зайнятих / всього | зайнятих (int) | всього (int) | `Завантаженість: X.XX` |
| Ресторан | калорійність 100 г = калорії / вага × 100 | калорії (double) | вага порції (double) | `Калорійність: X.XX ккал/100г` |

| Прокат авто | вартість = ціна × днів | ціна/день (double) | кількість днів (int) | `Вартість: X.XX грн` |

## Задача 2. Вартість прийому зі знижкою ⭐

### Умова

Напишіть програму, яка розраховує підсумкову вартість серії медичних прийомів з урахуванням знижки.

**Формула:** `сума = ціна × кількість × (1 − знижка / 100)`

### Формат вводу

| Рядок | Поле               | Тип      |
|-------|--------------------|----------|
| 1     | ціна одного прийому | `double` (грн) |
| 2     | кількість прийомів  | `int`    |
| 3     | знижка             | `int` (%) |

### Приклади

| ціна  | кількість | знижка | Вихід                  |
|-------|-----------|--------|------------------------|
| `500` | `3`       | `10`   | `Сума: 1350.00 грн`    |
| `200` | `5`       | `0`    | `Сума: 1000.00 грн`    |
| `750` | `2`       | `15`   | `Сума: 1275.00 грн`    |

### Підказки

1. **Різні типи вводу.** Ціна — дробова (`double`), кількість і знижка — цілі
   (`int`). Читайте кожне значення відповідним `Parse`.
2. **Головна пастка — цілочисельне ділення.** Якщо поділити `int` на `int`,
   результат теж `int`: `15 / 100` дає `0`, а не `0.15`. Прочитайте розділ
   документації про арифметичні оператори та знайдіть, як змусити ділення бути
   дробовим (підказка: хоча б один операнд має бути `double`).
3. **Знижка у відсотках.** «Мінус 10%» означає помножити на `(1 − 10/100)`.
   Слідкуйте, щоб `10/100` порахувалося як `0.1`.
4. **Порядок множників** не впливає на результат, але тримайте формулу
   читабельною: `ціна × кількість × коефіцієнт_знижки`.
5. **Вивід** — знову два знаки після коми, той самий формат `F2`.

📖 Документація:
- [Арифметичні оператори та цілочисельне ділення](https://learn.microsoft.com/dotnet/csharp/language-reference/operators/arithmetic-operators)
- [Неявні числові перетворення (`int` → `double`)](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/numeric-conversions#implicit-numeric-conversions)

| Домен | Формула | Поле 1 | Поле 2 | Поле 3 | Вихід |
|-------|---------|--------|--------|--------|-------|
| Готель | підсумок = ціна × ночей × (1 − знижка/100) | ціна/ніч | ночей | знижка % | `Підсумок: X.XX грн` |
| Ресторан | чек = ціна × кількість × (1 − знижка/100) | ціна страви | кількість | знижка % | `Чек: X.XX грн` |

| Прокат авто | вартість = ціна × дні × (1 − знижка/100) | ціна/день | днів | знижка % | `Вартість: X.XX грн` |

## Задача 3. Вік та категорія пацієнта ⭐

### Умова

Напишіть програму, яка зчитує рік народження пацієнта, розраховує вік і визначає вікову категорію.

**Формула:** `вік = 2026 − рік народження`

**Категорії:** 0–17 → `дитина` / 18–59 → `дорослий` / 60+ → `пенсіонер`

### Формат вводу

| Рядок | Поле            | Тип   |
|-------|-----------------|-------|
| 1     | рік народження  | `int` |

### Приклади

| рік народження | Вихід (рядок 1)  | Вихід (рядок 2)       |
|----------------|------------------|-----------------------|
| `2010`         | `Вік: 16 р.`     | `Категорія: дитина`   |
| `1990`         | `Вік: 36 р.`     | `Категорія: дорослий` |
| `1955`         | `Вік: 71 р.`     | `Категорія: пенсіонер`|
| `2008`         | `Вік: 18 р.`     | `Категорія: дорослий` |

### Підказки

1. **Ввід** — одне ціле число (рік народження).
2. **Вік.** У цьому завданні поточний рік зафіксовано як `2026` — щоб приклади
   були стабільні. Вік = `2026 − рік_народження`.
3. **Три категорії — три гілки.** Це класичний `if / else if / else`. Прочитайте
   в документації, чим відрізняється ланцюжок `else if` від трьох окремих `if`
   (у ланцюжку виконається рівно одна гілка).
4. **Порядок умов має значення.** Перевіряйте межі так, щоб кожен вік попадав
   лише в одну гілку. Продумайте на папері: 17, 18, 59, 60.
5. **Вивід — два окремі рядки:** спочатку вік, потім категорія (див. приклади).

- [Оператори порівняння](https://learn.microsoft.com/dotnet/csharp/language-reference/operators/comparison-operators)

## Задача 4. Артеріальний тиск ⭐⭐

### Умова

Напишіть програму, яка зчитує показники артеріального тиску і визначає категорію стану за стандартом AHA.

**Категорії:**
- систолічний < 120 **І** діастолічний < 80 → `норма`
- систолічний < 130 **І** діастолічний < 80 → `підвищений`

4. **Порядок гілок critical.** Ідіть від найсуворішої норми до найважчого стану.

## Питання для самоперевірки

Відповіді формулюйте своїми словами. Якщо не впевнені — поверніться до
відповідних сторінок документації з підказок.

1. Чому вираз `discount / 100` при `int discount` дає `0`? Що саме робить `.0`
   в `100.0`? *(напрямок: тип результату ділення залежить від типів операндів)*
2. У Задачі 4 третя гілка — `||`, а не `&&`. Наведіть конкретну пару значень
   тиску, для якої `&&` дав би неправильну категорію.
3. Чим `decimal` відрізняється від `double` на рівні представлення числа? Чому
   для грошей це критично, а для зросту в метрах — ні?
4. У Задачі 8 методи не звертаються до консолі. Як це допоможе, коли ці ж
   розрахунки знадобляться всередині класу `Patient` у Лабі 03?
5. Що станеться, якщо у `switch` expression прибрати гілку `_`, а на вхід
   надійде значення, якого немає в списку? Спробуйте і прочитайте помилку.
6. Чим `switch` як вираз відрізняється від `switch` як оператора? Коли який
   зручніший?
7. У Задачі 7 середнє рахується *до* циклу підрахунку «вище середнього».
   Чому не можна порахувати обидві речі за один прохід?
