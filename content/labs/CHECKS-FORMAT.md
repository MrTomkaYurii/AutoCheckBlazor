# Формат `checks.json`

Критерії приймання, за якими нейронка перевіряє кожне завдання лаби.
Файл лежить у теці лаби: `content/labs/lab-NN-slug/checks.json`.
Читається **наживо при кожній перевірці** — переімпорт не потрібен.

```json
{
  "tasks": [
    {
      "n": 1,
      "requirements": [
        "Звичайна вимога рядком — вага normal",

        { "text": "Ядро логіки: двопрохідний патерн без LINQ", "w": "critical" },
        { "text": "namespace ClinicApp; файловий стиль",        "w": "minor" },
        { "id": "fmt-tostring", "text": "ToString() у форматі \"[Id] ...\"", "w": "normal" }
      ]
    }
  ]
}
```

## Елемент `requirements[]`

| Форма | Значення |
|---|---|
| рядок `"..."` | вимога з вагою `normal` |
| об'єкт `{ "text": "...", "w": "critical" }` | вимога із заданою вагою |

Поля об'єкта:
- `text` (обов'язкове) — текст вимоги, який бачить студент і за яким грейдить нейронка;
- `w` — рівень ваги: `critical` \| `normal` (за замовч.) \| `minor`;
- `id` — стабільний ідентифікатор; якщо не задати, присвоюється автоматично (`r1`, `r2`, …).
  Задавай вручну лише якщо плануєш переставляти вимоги місцями й хочеш зберегти прив'язку.

## Як рахується бал

```
score = Σ(вага виконаних вимог) / Σ(вага всіх вимог) × 100
```

Стан: `≥ 80` — pass, `≥ 50` — warn, інакше fail.
Невиконана `critical`-вимога **не** обнуляє бал — вона просто важить утричі
(це «чиста вага», без жорсткого порога).

## Множники ваг

Задаються в `appsettings.json` — калібруються без деплою коду:

```json
"Grading": {
  "Weight": { "Critical": 3.0, "Normal": 1.0, "Minor": 0.3 }
}
```

Якщо всі вимоги завдання однакової ваги — бал такий самий, як при простому
підрахунку «виконано / всього».

## Поради

- Одна вимога = одна конкретна, перевірна річ (не «код працює»).
- `critical` — ядро завдання (алгоритм, ключова структура). `minor` — косметика
  (простір імен, формат повідомлення, назва змінної).
- Якщо для завдання немає `requirements` — нейронка виводить вимоги сама,
  і бал рахується без ваг (проста частка). Краще так не залишати.
- Номери `n` мають збігатися з номерами завдань у `instructions.md`.
